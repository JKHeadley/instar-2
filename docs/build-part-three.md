# Building and consuming the register

Part three implements `docs/07-the-declarations.md`. Its checks are named P3-NF-01 through P3-NF-30 in the tests and mapped from actual Vitest results by `scripts/check-register-contract-map.mjs`.

Run `npm run test:all` for strict TypeScript, compiled-package tests, architecture and source wiring checks, both parts' contract maps, and generated-output comparison. No prior `dist` is needed: typecheck precedes the emitted build, and E2E imports the emitted package only at runtime. `npm run register:generate -- --replay --commit <full-source-commit>` creates the offline conversion renderings; replay does not initialize a register or assert that a live spine is still unanchored. A source commit must contain the complete declaration/shape/document/code set. After changing those inputs, commit them and regenerate with that commit. The generated source pin makes the commit/content relationship explicit without asking a commit to contain its own hash.

The adapter reads `docs/01-the-rules.md`, standalone articles in `docs/rules/`, the glossary, the part-three definitions, and colocated declaration data from that commit. It refuses shallow trees, omitted input files and a pin that trails working source content. The one-time bootstrap shape data is `register-source/bootstrap-shape.json`; normal decoders read those shape values, not independent per-kind field lists. Generated output lives in `generated/`. Approved source prose is retained as the build brief requires.

Use `@instar/constitutional-types/register` to consume the public part-three API. Part one's package root remains the constitutional API; the closed inventory is unchanged. `decodeShape`, `decodeDeclaration`, `decodeReference`, `decodeExtract`, `decodeGeneration`, `decodeGenerationRecord`, and `decodeCheckRun` use part one's `defineDecoder` framework. Profiles and floors use the original constitutional decoders. Results flow through `consumeResult`; schema callbacks cannot construct a constitutional success or refusal themselves. All public decode inputs are `unknown`, and hostile-input tests include cycles, getters and non-data prototypes.

`generateRegister` receives the complete source declaration set, commit, extract and closed family-instance sources. It produces canonical, immutable entries, including pending landing facts and retained history. `generationOf` derives the content hash. A runtime consumer calls `loadRegister` with that generation and a `SpineReadPort`: it checks content, exact entering-force record, extract verification and current vector status. The resulting `VerifiedRegister` is the input required by `readRegisterEntry`; a shape-only result or a cast copy cannot bypass that load. A hash or a merge alone grants nothing. Part two owns the port's verified spine, facts, vectors and durable appends; references here are named import points, not duplicate fact types.

`resolveTerms` resolves structured references, generates `usedBy`, warns on unused definitions and unreferenced known words, and delegates adjective evaluation to part one's profile functions. `buildRuleGraph` computes holder edges from `holds`, never `standards`, and keeps reviewed, unreviewed, declared, partial, deferred and gap counts separate. `checkDeadlines` takes a clock measurement and never changes register bytes. Check-run verdicts retain failed/incomplete results; they do not reuse the effect-occurrence meaning of constitutional `Outcome`.

`constructGoverned` requires a declared id and kind; `checkPairing` checks the two-way relationship and rejects unpaired load-bearing caps. For `src/name.declarations.json`, the source adapter derives `declaredBy` from a unique matching literal core construct in adjacent `src/name.ts`; its actual function name need not equal the declaration id. It never trusts an authored location. Missing/other-file constructs remain phantom, and ambiguous sites refuse. Governed-state reads and decoder calls must occur in that same derived function, not another function in the file. Both conversion and normal ingestion use this binding. `check-register-wiring.mjs` examines actual imported port calls and declared governed-state decoder/record reads. Its boundary is explicit: static literals and named function scopes. Computed ids, reflection, config-loaded routes and plugin registration remain residual; `checkBoundaryCoverage` refuses a complete-enumeration claim for a residual-heavy kind. This is source reachability evidence, not a claim that every branch executes.

`planLandingCompletion` requires a system principal with live scoped grants, including revocation checks, and a spine-verified extract. It returns a completion and a generation record to append. It does not assert that an append happened. Completion diffs may fill only reviewed pending fields and corresponding extract rows; `verifyLandingCompletion` rejects content changes and history loss. Repeating a completed plan leaves its register unchanged.

The repository conversion currently has no approved deadlines or accountable standing routes for the original rule table's uncovered rules. The bootstrap anchor binds the approved corpus, initial schema and exact original rule declarations. The graph runs, reports those gaps, and emits an owned policy prerequisite for each unchanged original rule that lacks its deadline. This narrow exception cannot cover a new or edited rule, a declared expired deadline, an invalid holder, or an expired feature gate. All other checks run in bootstrap too. Normal mode permits no such prerequisites. Operator-selected deadlines must arrive as governing data, not be invented by the build. Semantic assessment and runtime guard freshness belong to part nine.

## Repair-round build workflow

The CLI requires an explicit initial `--replay`, `--bootstrap`, or a committed `--workflow register-source/<name>.json`. Subsequent `--check` reads the explicit mode in the generated manifest; it does not default an unknown build to bootstrap. Conversion check inputs may be supplied with `--checks register-source/<name>.json`, carrying the matching mode. `--now <unix-ms>` makes the clock input reproducible in fixtures; real CI uses its actual clock so passed deadlines fail.

The conversion trust root is the canonical anchor digest captured from baseline `52772ae`, pinned in the protected checker release (`scripts/build-register.mjs`), not read as authority from the candidate. The candidate anchor, shape, original rule hashes and document hashes must agree with that pin. Changing both candidate shape and candidate anchor cannot relax it. Changing the pin is a protected checker change requiring review; parts nine/eleven still own independent enforcement of toolchain approval. This pin is a reproducible baseline binding, not a fabricated approval record.

Actual `--bootstrap --provider <trusted-module.mjs>` additionally requires the part-two adapter's `verifyBootstrap({anchor, commit, checkedAt})`. That method must verify the conversion approval and current absence of a first entering-force record, returning a constitutional Result containing `{phase: 'converted-unanchored', binding, fact}` with the exact request binding and verified part-two FactEnvelope reference. A provider omission, anchored phase, stale clock or mismatched binding refuses. After anchoring, only the normal workflow can initialize a candidate. The adapter is a trusted dependency supplied by the invocation, never by workflow JSON; the production implementation remains a P2 seam. Offline `--replay` neither accepts a provider nor exercises this transition; its manifest explicitly says `mode: replay` and `authority: shape-only`. It cannot establish current phase, append facts, or replace `loadRegister` verification.

Normal workflow JSON supplies `mode: normal`, `branch`, `conversion` (the emitted conversion.json documents/source set, committed as input), `parent: {register, generation}`, mirrored `extract`, `runs`, `catalog`, `landedParts`, `references`, and enumeration `claims`. Rule numbers from the authoritative source corpus must be present exactly once. The workflow bytes themselves must be present in the source commit. Use `--provider <module.mjs>` for the trusted P2 adapter exporting `provider`; JSON cannot pretend to implement verification. That adapter supplies the existing SpineReadPort plus `verifyShapeChange(binding)`, optional verified `types`/governed-state `separations`, and `resolveReference(reference)` for externally owned records. The SpineReadPort part is now implemented: `createRegisterSpine` in `@instar/constitutional-types/facts` answers extract verification, entering force and vector currency from the verified chain, and `extractGovernedChain` derives the mirrored extract itself. `verifyShapeChange`, `resolveReference` and `landingStanding` remain explicit provider prerequisites.

The entry point calls source wiring, pairing, enumeration-boundary coverage, governed-state read/decoder checks, separation of writer/executor standing, the rule graph, deadlines, and terms before rendering. Source observations come from C, never an author-provided success flag. Fixture/probe reference entries need catalog artifacts with a committed path and canonical content hash. Decoders resolve against the actual constitutional/registered decoder inventory. Record references need the verified provider.

For shape changes, `shapeChange` binds the parent generation hash, candidate shape hash, and exact approved document path/hash. The provider must resolve approval of that exact binding. Ordinary declarations validate against both the verified parent's shape and the carried candidate shape. The candidate cannot loosen its own validation, and incompatible tightening or missing newly required facts refuse before generation rather than producing an unloadable register. Compatible approved transitions round-trip through `loadRegister`; incompatible migrations require a separately designed staged change, not silent relabelling.

Completion workflows use `mode: completion`, the committed mirrored extract, and `pending` reviewed register. The provider also supplies `landingStanding`. The workflow/mirror commit M is distinct from the pending register's source commit C, avoiding a self-referential commit hash. Reviewed code and documents must be unchanged; the generated completion must equal source regeneration and may only settle the allowed pending fields and extract rows. The emitted completion is still a proposal requiring P2 append.

Nested fact schemas now specify local scope reasons, store agreement targets/invariants/checks, per-stimulus parser authentication and event-id authority, subsidy/model verification facts, feature gates, operator requests, observation references, and sentinel moments. A multi-rung boundary is nonempty and exclusive with top-level rung facts; each rung validates its full obligations. These serialization names are the concrete initial P3 schema, not rival P2 types.

`shape.factSchemas` and generated `fact-schemas.json` publish generation-record and check-run-record registrations separately from governed categories. `registeredFactSchemas` and `decodeRegisteredFact` give P2 discovery/dispatch without a local schema copy.

Retired entries remain history; retired, dark and soaking holders do not contribute current enforcement edges or totals. All P3 suite locations are protected, and the executed P3 contract map refuses any participating file outside the protected patterns.

Tests cover unit behavior, component integration with part one's real decoders, and the actual compiled build command. The part-two spine adapter's read side is exercised for real in `tests/integration/register.test.ts`: recorded version facts, recorded explicit-yes approvals and recorded generation facts drive `loadRegister` and `planLandingCompletion`, so approval history settles from the chain rather than staying pending. Shape-change approval, reference resolution and landing standing are still exercised with named test ports. CI runs regenerate-and-compare on x64 and ARM64 and compares the resulting bytes. Local tests alone do not claim execution on a second architecture.

Multi-machine posture: canonical output depends on explicit C/E inputs, not local time, checkout ordering or machine identity. A machine's ability to verify a current extract remains relative to its spine replica. The build adapter's clock is attribution context only; deadline checks receive an explicit measurement. Generated files are disposable and regenerable; original source documents and record history remain intact.

Side effects and rollback: this adds a register subpath, scripts, tests and generated files. No external service, runtime deployment or production spine is modified by generation. The CI matrix adds an ARM64 run and the package's full test command now checks register outputs. Reverting the part-three commits removes those additions; it must not remove any subsequently admitted spine facts. The source-pin file allows reproducing the prior rendering. Toolchain paths are declared protected artifacts; independently enforced repository/runtime protection remains with the designated later owners.
