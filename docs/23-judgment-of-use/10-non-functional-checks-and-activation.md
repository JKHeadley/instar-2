**Rule — acceptance traverses the real owners.**
**Checks: P23-NF-02–22.** For each runtime row, require unit boundary evidence,
real public/HTTP integration, production-initialization lifecycle and explicit
wiring checks that reject null/no-op adapters. Use real owner ports and observable
outcomes for consequential paths. Check both sides with realistic semantics;
mock schema success is not the production positive. Register every criterion,
store, projection, producer, consumer, resource policy, floor/default and check.
The section 11 fixtures name the exact outcomes; owner refusal preserves inputs.

Basis: Purpose's evidence constraint; rules 34/35/49/65/69; existing owner testing
contracts and Part 21 activation convention.

**Rule — activation is a conjunction, not an implementation flag.**
**Checks: P23-NF-16/17/19/20/21/22.** Documentation approval, all applicable
owner grants and their implementation, registered current consumer defaults,
independent control of grading, unit/integration/lifecycle evidence, migration
parity and applicable study permissions are separate conditions. A/B local
activation requires NF-02–11 and NF-13–22. Commons export additionally requires
NF-12 and C. A local loop does not depend on enabling fleet sharing. The initial
C arm is offline/background under NF-13/14/16/17 and never controls a real action.
No live C activation is specified here; any such consumer needs its exact
operator-approved rule exception and measured benefit through the existing owner.

Basis: Purpose's “Who decides what” and authority/evidence constraints;
rules 57/65/86/94/95. Classification alone is not a waiver of ordinary reachability.

exercise. Neither provides Part 23 runtime acceptance, an executed real-case
pilot, human wisdom comparison or independent design convergence.

Basis: Purpose's evidence constraint; rules 65/108.
