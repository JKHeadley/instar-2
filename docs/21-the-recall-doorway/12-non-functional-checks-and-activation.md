**Rule — resource tests name the environment and the unavailable arms.** Rules 13, 34,
39, 40, 43, 62 and 75; **checks: P21-NF-08/16/18/19/21/23**. An execution report
records hardware, OS/architecture, exact artifacts, account/provider mode, source size, permitted
history size, write/read ratio, peak workload, faults, warm/cold cache, frontiers and timing clock.
Use the same workload on supported x64/arm64 implementations and report platform limitations.
For proposed indexing freshness, test 200-message/1 MiB batches at 1x and 2x the installation's
declared peak arrival rate, with proposed oldest-pending targets of 60 s for lexical metadata
and 5 min for optional dense/derived work. These are OD-03 defaults; no capacity is asserted
without a declared measured rate. At saturation, retain pending source and expose lag; exact
custody lookup remains the read fallback, subject to its own cap.

**Rule — activation follows actual owner composition.** Rules 34, 44, 47, 62, 65, 69,
72, 73, 78, 105 and 111; **checks: P21-NF-02/17/19–24**. P21 implementation must add
unit tests, full HTTP/public-pipeline integration, production initialization E2E lifecycle and
wiring-integrity tests for every injected component. Test both sides of semantic boundaries,
not only decoding. Enumerate every principal producer and outgoing consumer in the register;
fault a dependency to prove it delegates to real code and exposes the intended failure.

Implementation adds agent awareness, capability inventory, operator context/coherence views,
mobile-complete pending decisions and migration parity through the owning templates/update path.
This documentation-only draft does not edit those owners or claim those consumers exist.
Feature posture is **design-only, inactive**. Proposed maturation is test installation, then
development installation, then fleet only on each applicable check and real surface proof.
At implementation admission, the owner must assign a named graduation/recheck date and accountable
reviewer; an unassigned date inhibits activation rather than becoming an indefinite dark feature.
The semantic-review mode has its own approval and evidence, independent of A/B activation.

**Value — honest partial delivery is inspectable.** Existing owner fixtures can prove that a
dependency shape is understood. They cannot prove that a person received a coherent answer,
that compaction accounting landed, or that another machine's private history is safe to use.
Review reports mark those arms unavailable until the precise seam and real composition pass.
