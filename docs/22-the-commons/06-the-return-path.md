## 6. The return path

**Rule — a release carries evidence and remains a proposal until locally admitted.** **Checks: P22-NF-11/12.**
The release manifest binds immutable artifact/version/content hashes, parent lineage,
scenario/proposal identity, exact human approval and delegation, placement record, current
support and dissent, owner compatibility requirements, migration/rollback plan and outcome
follow-up. Signatures authenticate an approved issuer; they cannot replace any of those fields.
Shared scenario packages, bounded capability/procedure packages, and candidate governing
amendments remain different artifact kinds with their own consumers and approval boundary.

The receiving agent verifies destination trust, signature, bytes, current support, compatible
owner generation, scoped installation authority and stop/revocation before installing through
the effect/assembly owners. A successful download creates no installation authority. The
local acceptance record joins installed bytes to measured outcomes, with unavailable evidence
shown explicitly. An operator-run front has no special privilege over the canonical front.

Basis: Big picture §8, improvement keeps provenance, and §9; purpose constraints 3/4 and non-widening authority; rules 24/28/44/49/90/111; G4.

**Rule — governing material is never rewritten by the commons.** **Checks: P22-NF-10/11.**
A proposed rule, term, register shape or protected artifact follows its owning version and
approval process. A release cannot enroll sharing, expand fields or audiences, change standing,
disable loss detection or amend the purpose. Exact approval invalidates if bytes or scope
change. Even an operator-approved upstream artifact still needs the receiving agent's current
local installation authority; neither side can silently substitute for the other.

Basis: Purpose “Who decides what,” authority constraint; big picture §8; rules 57/86/90/94.

**Rule — withdrawal and later correction reach every known dependent.** **Checks: P22-NF-08/12/19.**
Reverse support links identify affected scenarios, proposals, published versions and local
installations. A validated correction invalidates support immediately in current local views;
healthy propagation meets E7. Revocation stops queued sends and future admission. A disconnected
agent sees missing currency and cannot claim current support. The release owner issues a
signed hold/withdrawal notice, while local owners decide a permitted rollback or hold under
current authority. A withdrawn package is never silently deleted from its historical record.

A receiver can acknowledge deletion/withdrawal only for custody it controls. Already disclosed
knowledge, dishonest copies and third-party backups are not recallable by assertion. Deletion
receipts, backup expiry and tombstones record what was actually performed under agreed terms.
The operator can still inspect reachable status while the commons or normal model path is down.

Basis: Coherency, trust and constraints 2/3; rules 42/45/77/83/95/108; R2 hostile-front limits; G2.
