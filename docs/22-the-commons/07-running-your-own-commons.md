## 7. Running your own commons

**Value — one address selects an operated commons running the same code.**
The developer-operated front is a default destination, not an authority ceiling. An operator
can deploy the same versioned receiver/processor/release package, provision isolated storage
and keys, appoint a review owner, and then change the configured commons address. No fork or
private alternate schema is required. That address flip selects an already provisioned service;
it cannot provision storage, credentials, staffing or trust on its own.

Basis: Sovereignty and big picture §9 fractal self-hosting; R1 reusable/operated split; OD-01/03.

**Rule — switching destinations changes routing, not consent.** **Checks: P22-NF-05/06/15.**
Pause the old outbox; retain its custody and unresolved receipts. Validate the new endpoint
and signer through the owner's transport/security policy, including authenticated transport,
redirect handling and permitted network scope. Do not silently follow a redirect into another
commons or private network. A deliberately local private commons requires its own permitted
local destination; the canonical public-front policy does not authorize that address.
Establish destination-scoped enrollment, grants and retention terms before new exports.
No old richer payload is retargeted, no global identity is sent, and no signing trust is copied.
Cross-commons forwarding is a new export subject to all originating restrictions.

Basis: Trust, sovereignty and non-widening authority; rules 28/29/86/95; R1 endpoint limits; R4 address boundary; G2.

**Rule — same-code parity is a lifecycle claim.** **Checks: P22-NF-15/19/20.**
Exercise two isolated stores with the identical package hash through enrollment, first send,
duplicate, restart, correction, review, release, install, withdrawal, destination change and
recovery. The second commons must not read the first one's data, grants or operator count.
A managed-deployment-only adapter cannot be necessary for self-hosting. Package updates preserve
custom addresses, disabled sharing, private grants and curated state. Where full operator
independence cannot be established across destinations, report unknown instead of merging counts.

Basis: Big picture §9; rules 30/44/49/69/111/113/115; section 11 migration and section 14 dependencies.
