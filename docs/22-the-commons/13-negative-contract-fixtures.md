## 13. Negative contract fixtures

**Rule — test the forbidden result and the permitted neighbor.** **Checks: P22-NF-02–20.**
Each case below is a named future fixture, not an assertion of test execution. Its NF ids
inherit every dependency in section 14. Unit tests validate shape/logic, integration tests
exercise the authenticated full pipeline, and production lifecycle tests use real owners.
An accepted negative retains an attributable failure trace; a refusal must name the actual
owner boundary without leaking the rejected body. Run the same cases through both commons
instances and across restart where custody or budgets matter.

**Rule — fixture provenance never becomes fleet outcome evidence.** **Checks: P22-NF-09/10/17.**
Synthetic adversarial examples exercise controls. Only owner-validated real graded cases
can support production benchmark membership or generalized judgment lessons. Known-count
synthetic C populations test estimator error, not real-world prevalence or wisdom. Every
10,000-attempt stress arm must include semantic boundaries above; raw volume is insufficient.
