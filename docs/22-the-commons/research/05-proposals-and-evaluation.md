# R5 — Proposals and evaluation for the commons

**Status: research recommendation for design review. Governed. Evaluation plan only; no experiment results, deployment or sharing approval.**

## Decision and evidence boundary

**Value — recommend a case-and-proposal commons first, with a gated federated evaluation
extension.** Proposal A below supplies the accountable fleet loop: local evidence, permitted
derivatives, verified admission, review, versioned proposals and a measured return path.
Proposal B adds stronger evaluation while originals stay local, after the owner seams and
execution/privacy controls are proven. Proposal C is a possible prevalence channel, not a
substitute for standing-bearing cases or judgment review. This recommendation selects a
direction for D1 review; it neither asserts that the options work nor starts building.

## Shared admission floor for all proposals

**Rule — implement standing-weighted, outcome-graded, pillar-placed admission structurally.**
**Check:** the same local and front validators require all rows below, with positive and
negative fixtures at each transition. The local grant and effect doorway cannot be bypassed
by a canonical front or a self-hosted one. Grounds: R4's standing and placement model;
rules 28/29, 57/58, 85/86, 94/95 and 108 at
`docs/01-the-rules.md:237,268–269,282,294–295,302–303,340`.

| Gate | Required evidence and decision | Failed or unknown disposition |
|---|---|---|
| Export | Current destination-bound per-agent grant, custody/audience floor, closed R2 schema, transformed payload receipt | Local record retained; no send or retry; richer attachments require separate opt-in |
| Identity and standing | Verified pseudonymous enrollment plus independently resolved role/scope/delegation; retain grader and interested-party status | Anonymous/unverified signal lane, no accepted grade or independent-operator count |
| Evidence | Canonical case and causal assessment chain; actual outcome and explanation graded separately; evidence strength and time horizon explicit | Unproven/disputed, never made complete by popularity or fluent model prose |
| Placement | Exact lesson, purpose hash, deciding pillar and derivation, all-floor conflict check; R4's placed/contradiction/gap/unproven disposition | Contradiction rejected; gap recorded as candidate amendment; unresolved lesson inactive |
| Benchmark | Real graded case, permitted replay or explicitly local attested evaluation, owner-resolved compatibility and frozen rubric | No public scenario from a content-free complaint; no synthetic case counted as real production evidence |
| Promotion | Independent cases, outcome thresholds, blinded independent review, accountable human approval of exact proposed artifact | Preserve evidence and dissent, hold proposed change; receipt is not approval |
| Return | Versioned artifact/provenance, signing trust, local compatibility and current scoped installation authority; outcome hook and withdrawal path | No installation or governing rewrite; local loop remains usable |

**Rule — consequential effects retain their existing owner.** **Check:** export, publishing,
release, spending and authority changes are registered and classified against all four tests
in `docs/00-the-purpose.md:76–92`. A content-free upload can still be consequential because
the agent cannot undo the receiver's custody. A non-user-facing agent message is not thereby
ordinary. Each repeated export checks current consent; a signed evaluation invitation does
not widen scope. Authorized research drafting here does not authorize those future effects.

**Rule — consequential pipelines inherit supervised execution.** **Check:** a commons
pipeline on which a consequential effect depends includes at least Tier 1 model supervision,
with each programmatic step and its validation recorded through the existing judgment doorway.
The supervisor can narrow allowed actions, never override export, secrets, money, standing or
approval floors. A missing supervisor makes that pipeline unavailable for consequential work.
This applies rule 38 (`docs/01-the-rules.md:275`) using the purpose's definition of critical;
E12's production-composition check must exercise the supervisor, not merely find a configured name.

## Proposal A — Accountable case-and-proposal commons

**Value — A closes the ownership loop with the smallest new trust surface.** Each agent
retains original evidence and runs the local loop. After enrollment it emits R2's closed
derived-case fields from existing owner ports into a durable outbox. The shared code can run
as the primary developers' canonical front or an operator's private collective. Front custody
and role validation precede clustering; a review owner records admission and promotion
dispositions. Exportable real scenarios and bounded procedural/capability changes travel back
as separate versioned packages. This carries forward the reusable factory and operated-owner
pattern established by `1x:docs/specs/feedback-factory-migration.md:157–162` and
`feedback-factory-operating-drain.md:100–125,174–186`.

**Rule — A provides an auditable state machine.** **Check:** a canonical export has one
current state and immutable transition receipts through local-recorded, queued, front-stored,
admitted/signal-only/rejected, reviewed, scenario-eligible, proposed, approved, released,
locally-installed and outcome-reviewed. Separate scenario and proposal branches cannot imply
one another. Corrections supersede assessments and invalidate downstream support; they never
erase earlier verdicts. Loss/stall reconciliation covers every nonterminal state. Triage may
use bounded model judgment under floors, with inputs/decisions logged by the owning doorway;
it cannot manufacture a human approval. A store full of clusters with no review owner fails.

**Rule — A does not centralize private judgment records to obtain explainability.** **Check:**
default fields contain codes and approved public identifiers, never original rationales,
correction text, private content hashes, embeddings or gradients. Exact reasons and sources
remain locally reviewable by permitted reviewers. A separately approved replay includes its
loss record and access policy. A front unable to inspect evidence labels it attestation;
that label cannot satisfy an independent-proof requirement. This follows R2 and
`docs/20-measurement-ledgers/07-feature-benchmark-and-burn-joins.md:99–109`.

**Value — A's expected benefit and limit.** It can turn recurring failures into owned work
and shared real scenarios without a fleet-wide remote execution service. Its likely limit is
human review effort and the fraction of cases that can be safely reproduced. Those are
hypotheses for E2/E5/E8 below. It will miss some private cases and cannot establish prevalence
from a complaint-enriched inbox. A rare verified floor violation still merits investigation
without passing a popularity or minimum-cohort threshold.

## Proposal B — A plus locally admitted federated evaluation

**Value — B brings a fixed comparison to permitted local histories.** The front distributes
a signed, content-addressed evaluation package with public scenario definitions, candidate
artifacts, rubric version, input-access declaration, allowed outputs, maximum calls/cost,
expiry and a locally enforceable repeat budget. Participating agents explicitly admit it,
execute it in isolation, and export only approved bounded results. The orchestration analogy
is [MedPerf, published 2023-07-17](https://www.nature.com/articles/s42256-023-00652-2);
the inference for Instar is that local custody may widen evaluation coverage, not that local
execution proves confidentiality or validates wisdom.

**Rule — B's front cannot query memory arbitrarily.** **Check:** admission binds the exact
package and candidate, limits read scope to owner-permitted fixtures, disables external
dispatch, blocks undeclared network/filesystem access, meters calls and outputs, and rejects
changed/repeated/adaptive queries beyond the approved plan. Provider exposure during evaluation
is itself a boundary check; local storage does not mean the model provider saw no private data.
A package signature proves origin only. A front outage leaves a local resumable/cancelled
record and never interrupts the local principal's normal work.

**Rule — B uses the measurement owners' comparison contract.** **Check:** Seven resolves the
full prompt/context/floor/schema/model/scenario/evaluation compatibility tuple; Nine supplies
complete current grades; Twenty counts planned executions, costs, concentration and
missingness. Missing public seams yield unavailable, not a commons-created substitute.
The non-executable conditions documented at
`docs/20-measurement-ledgers/07-feature-benchmark-and-burn-joins.md:42–78` are an explicit
activation prerequisite. Private compatibility that cannot be exported remains locally
attested and centrally non-comparable, as specified by R2.

**Value — B's expected benefit and limit.** It may test A's proposals on more independent
private histories and find regressions before release. It adds package supply-chain risk,
resource consumption, covert output channels and repeated-query leakage. It is worth adding
only if E5/E8 show incremental utility over A within E3/E6/E9 floors. Keeping raw data local
alone is not a privacy proof. Automated model-weight updates remain outside this proposal.

## Proposal C — A separate privacy-bounded aggregate channel

**Value — C estimates broad failure prevalence while exporting fewer exact contributions.**
Local agents form clipped, fixed-vocabulary category summaries, randomize them locally under
a reviewed differential-privacy mechanism, and report only bounded noisy values. Operator-scoped
contribution budgets cover all enrolled agents. The front shows uncertainty and suppressed
cells; exact evidence remains local. R3's differential-privacy and RAPPOR sections distinguish
local randomization from central curator trust and from secure aggregation. C is an optional
channel beside A, not a way to convert anonymous noisy totals into standing-bearing grades.

**Rule — C needs an explicit privacy model before it can claim a guarantee.** **Check:** pin
the neighboring-dataset relation to replacement of one verified operator's full permitted
contribution; bound each operator's contribution across its agents; specify the local mechanism,
clipping, release cadence, collusion and destination assumptions; persist the composed budget
across restart, key rotation and commons changes. Unverifiable operator grouping means this
operator-level guarantee is unavailable. Do not reset lifetime loss at a window boundary.
If secure aggregation is later added, its threshold/dropout protocol needs a separate reviewed
specification; C does not claim that protocol is already chosen or necessary for local DP.

**Value — C's candidate experimental privacy profile.** Use at most one scheduled contribution
per operator per seven days, clip to one normalized category vector of L1 norm at most one,
and allocate at most epsilon 1, delta 0 cumulatively for the entire 90-day pilot, across all
its destinations. Release no category estimate with fewer than 50 verified independent
operator contributors. The mechanism must be proven to meet that operator-level local bound;
these numbers are a budget and a utility experiment, not such a proof. Reject on exhausted
budget or failed grouping. Privacy tolerance is candidate amendment G2 below; nothing here
authorizes spending that budget. Small fleet utility may be too weak even to rank common causes.

**Rule — C cannot promote a lesson from a noisy majority.** **Check:** aggregate results may
nominate an investigation but never satisfy A's case, grade, standing, independence or human
approval gates. Synthetic known-count simulations can test estimator utility without claiming
production outcomes. A statistically strong signal to breach a pillar is still rejected.
If consented real cases cannot later support the proposed change through A, the result remains
a prevalence estimate rather than fleet wisdom.

## Comparable evaluation protocol

**Rule — seal the experiment before exposing held-out cases.** **Check:** an approved run
manifest records protocol/content hashes, candidate and baseline packages, owner port versions,
membership and independence claims, allocation, budget, rubric and private frozen labels,
outcome windows, exact planned identity set, exclusions, statistical code/seed, thresholds,
reviewer identities/conflicts, export terms and stop policy. An independent custodian holds
labels and the holdout; the proposal author cannot grade its own success. Missing manifest
fields, owner seams or authorization means not executable, not a failed or passed experiment.
Grounds: rule 65 at `docs/01-the-rules.md:221`, big picture `:299–311`, and Part Twenty's
planned-population/current-grade rules at `07-feature-benchmark-and-burn-joins.md:16–40`.

**Value — three arms and one fixed baseline.** Baseline L is the same local loop and current
package with fleet participation off. A, B and C receive the same bounded discovery budget
and development pool; C can nominate work only through A's review path. Freeze one resulting
candidate package per arm before holdout access. Evaluate each candidate against L on identical
held-out local opportunities and report the mechanism cost as well as package outcomes.
This tests the proposals' end-to-end usefulness under equal budgets, not an isolated causal
effect of one algorithm. Identical resulting packages imply no demonstrated outcome advantage;
mechanism cost/coverage can still differ. B-versus-A is a separately preregistered paired
incremental comparison on these same candidate packages.

**Value — the candidate real-case sample.** Reserve at least 300 real graded development
episodes from operators outside the held-out cohort. Hold out 600 different real canonical
opportunities from 20 independently enrolled operators, 30 per operator. Before candidate
selection, stratify the holdout into ten cells of 60: the four R2 recall causes; wrongful
disclosure; wrongful withholding; permitted internal use without disclosure; later-outcome
reversal of immediate approval; benchmark/regression feedback; and correction/reason refutation.
Within each cell include 20 failures, 20 matched successes and 20 legitimate-hold or
unavailable-evidence controls. Assign one primary cell before grading to avoid double counting;
preserve overlapping diagnostic tags separately. Originals and sensitive labels stay local.
If the real corpus cannot fill those cells, report insufficient evidence, not synthetic fillers.

**Rule — distinguish retrospective validity from later outcomes of a changed agent.**
**Check:** historical replay uses decision-time input, with later facts available only to
graders, and stops at prepared effects without dispatch. It can establish behavior against a
frozen outcome-informed rubric; it cannot establish what would actually have happened after
an unsent candidate action. After all offline gates pass, a separately authorized prospective
confirmation uses a fresh cohort: 40 independent operators allocated by a sealed random seed,
20 to L and 20 to the recommended candidate, with no crossover during the observation window.
This avoids memory carryover being treated as a washout. Predeclare at least 30 consecutive
eligible opportunities per operator, 600 per arm, with each case observed at immediate, seven-day
and 30-day horizons. All cases must mature through 30 days before the final claim; further harm
reports reopen it. Recruitment and follow-up stop 90 days after pilot start; an unmet sample is
inconclusive. Authority and effect floors hold in both arms and no harmful action is deliberately
authorized for statistical balance.
Use the first 30 eligible opportunities after allocation per operator for the primary analysis;
additional opportunities remain a separately reported safety/diagnostic population.

**Rule — a successful outcome includes a valid reason.** **Check:** score conclusion,
reason, observed effect, sharing harm, withholding harm, scope/floor adherence and evidence
availability separately. The primary binary pass requires the registered outcome criterion,
a non-refuted reason, and no floor violation. A happy recipient does not erase an unauthorized
disclosure; silence does not prove rightful withholding; unresolved later consequences remain
unknown. Immediate approval is diagnostic only. Current later evidence supersedes an earlier
factual grade causally, preserving both records. This operationalizes purpose `:53–65` and
rule 108, rather than training the system to seek approval.

**Rule — missingness and correlation cannot improve the estimate.** **Check:** all planned
executions remain in the denominator, including refusals, cancellations, pending and conflicted
grades. A correctly graded refusal can pass its criterion; missing evidence cannot. Correct
handling of an unavailable-evidence control can have a complete grade; that differs from an
outcome the grader cannot determine. For each offline operator compute the paired
candidate-minus-L difference within each evidence-strength and standing stratum. Prospectively,
compute each operator's mean in its assigned arm, then compare equal-operator arm means;
there is no invented within-operator counterfactual. Report raw counts, coverage and shares. For the primary
promotion test use a conservative missing-data bound: unknown candidate scores are zero and
unknown L scores are one; also publish the opposite bound and complete-case estimates.
No headline mixes attestation/inference with independently verified evidence. Cluster inference
at operator level and separately disclose shared model/grader/incident lineage; 20 operators
does not establish independence if all copied one source incident.

**Value — fixed inference method.** Use 10,000 paired operator-cluster bootstrap resamples,
seed 220205, for offline candidate differences and the incremental B-minus-A comparison.
Keep each cluster's cases together. There are four planned offline comparisons; use two-sided
98.75% percentile intervals for each (Bonferroni family error at most 5% under the interval
method's assumptions). Test no additional candidate on this holdout. For prospective
confirmation use a two-sided 95% interval from 10,000 arm-stratified operator-cluster bootstrap
resamples with the same recorded seed. These are proposed analysis choices, not a guarantee
of coverage with a small or dependent cohort. Publish distributions and sensitivity to leaving
out each operator; no claim of sufficient power is made before real variance is known.

## Preregistered thresholds and negative fixtures

**Value — fix the following candidate thresholds together.** None can compensate for another:
privacy/authority floors are vetoes, utility thresholds test useful gains, and throughput checks
test whether the loop operates. Exact boundary equality is accepted for minimums/maximums,
except a positive confidence lower bound must be strictly greater than zero. A quality gate
that lacks enough data is inconclusive. All quantities are proposed targets, not measured values.

| ID | Acceptance threshold | Protocol and falsifier |
|---|---|---|
| E1 Standing and placement | Zero forbidden promotions or forged grades across 10,000 generated admission attempts; 100% of promoted artifacts have an exact pillar derivation, independent evidence and human approval | Cover every gate and both boundary sides, including expired grants, operator from another scope, 10,000 cloned agent votes, anonymous reproducible bug, an operator's wrong factual reason, equal-standing conflict, missing pillar and a pillar contradiction; duplicate votes must not change authority |
| E2 Custody and complete loop | Zero lost or double-adopted canonical cases across 10,000 fault-injected transitions; 100% of admitted cases receive an owned review disposition within seven days; healthy reconciliation p95 at most five minutes | Crash before/after persist/receipt/grade/release, reorder and replay messages, 429/503 backoff, offline front, missing owner, non-persisting 200, corrected grade and withdrawn release; measure dispositions including held/rejected, separately from successful improvements |

**Rule — test implementation at all three tiers before claiming these controls hold.**
**Check:** unit fixtures cover pure schema, grants, assessment succession and placement;
integration fixtures exercise authenticated local API → exporter → front → store → review →
return; lifecycle fixtures use production composition with real registered owner dependencies,
crash/restart and a same-code second commons. Include a positive eligible case next to every
negative fixture so a system that rejects everything cannot pass. The 10,000-attempt counts
are stress floors, not a substitute for semantic coverage. Independent review checks the full
trace and accepted residue; counts alone do not establish convergence. Research-document
validation is separate from this future implementation evidence.

**Rule — fleet sample floors do not suppress a local correction or a defect report.**
**Check:** one independently reproduced counterexample can open owned repair work and support
a bounded local correction through its existing authority. It cannot be advertised as a
generalized fleet judgment lesson before E7 and the other promotion gates hold. Urgency raises
review priority, not standing, and cannot bypass the constitution or release approval.

**Rule — stop, preserve and return an honest verdict.** **Check:** any authority or privacy
violation immediately stops the affected arm's exports/effects, preserves permitted evidence,
notifies its accountable owner through the existing authorized surface, and holds dependent
promotions. E1/E3/E11 failures cannot be offset by E5. A cost cap stops further work, leaving
planned missing members in the denominator. An unmet sample, unknown price, absent owner seam,
unreliable grader or insufficient interval precision yields inconclusive/unavailable as
appropriate. Publish a protocol-bound pass/fail/inconclusive matrix with raw populations,
uncertainty, rejected cases and limitations, rather than one reward score. Later harm can
withdraw a prior passing disposition; it does not rewrite its historical record.

standing or export private reasons to manufacture success. If B later demonstrates the required
additional gain, it becomes A's evaluation extension. If C passes, it supplies prevalence
signals, never permission. Only the operator changes the judge of these judgments.
