## 14. Operator decisions and honest limits

**Value — the required outcome.** A person keeps talking to the same capable agent across
messages, tools, compaction, restart and worker replacement. The agent remembers and accounts for
its work, uses the accounts granted with its role and remains reachable. Vendor history improves
speed; it does not hold identity, promises or authority hostage.

**Value — decisions and their dispositions.**

| Decision | Disposition and reason |
|---|---|
| One port, common queue, three interchangeable workers | Rules 30/68/115 decide the boundary. The five-method shape and one-active-input default are engineering choices that reuse existing owner stores. Measure turn latency, queue age and recovery rather than adding another store. |
| Explicit control and reply/terminal observations | Engineering default under Rules 26/42/59/68. Private controls and guessed completion cannot reliably implement stop or return the answer. No constitutional rule fixes the method count at four. |
| Resume as optimization, rebuild as required behavior | Rules 47/68/96/110 decide it. Losing a vendor transcript cannot erase the agent. Context delivery evidence does not claim understanding. |
| Current scoped tools/accounts with all calls metered | Purpose role, safeguards, durable cause and sign-off rules; Rules 4/29/60/63/75/100/114. Empty tools or accounts is not a blanket safety mechanism. |
| Compact diagnostic events by default | Engineering default under Rules 7/39/116. Required audit captures remain; extra pane snapshots need an actual diagnostic use and the deployment's privacy policy. No new age-deletion policy. |
| One-machine irreversible account actions | Candidate constitutional amendment, for the operator only; exact conflict below. The adapter cannot decide it by relabelling a write as a tool. |

**Rule — constitutional conflict stops the affected design decision.** Purpose single-machine
functionality, supported deployment shape and sign-off rules; Rules 49/94/103; checks
P13-NF-06/18/40/48. The governing purpose says:

> “An Instar agent with only one available machine must still be fully functional.”

It also permits local irreversible dispatch “only for the fixed profile's closed set” and names
“its installed paid provider call, its reply-only Telegram `ordinary-reply` send, and its text-only,
reply-only Slack `ordinary-reply` send in one workspace to the bound operator's pre-bound DM or
thread.” The same rule says “an operation outside the set” refuses. Yet the sign-off rule says:

> “Everything else inside the agent's role is ordinary, including sending messages and using the accounts that go with the role.”

A one-machine email send or irreversible account write inside the role needs behavior the closed
set excludes. This design stops short of authorizing or specifying an admission exception for
that case. It neither edits the constitution nor adds a local fallback or silent bypass. The
operator question is: should the closed local profile include in-role irreversible account
operations with their authorization and full causal prefix durable before dispatch, under the
same named sign-off conditions and accepted loss model? The effects design owns both possible
answers. Until resolution, this contract can carry a typed refusal preserving the request;
connected-account reads and ordinary reversible bounded actions keep their existing local path.
That partial path is not claimed to satisfy the full one-machine employee goal.

**Value — questions for the operator.** The preceding constitutional scope question is the
one direction/authority question in this part. There is no request for another permission to use
a conforming adapter or a granted account. Concrete route defaults, bounds, event transport and
safe-boundary scheduling are engineering choices; declaration of a limit names the rule requiring
it. The joint review also needs Five's exact work correlation and Eight's registered tool-effect
schema. Those are owner integration questions, not reasons to ask the person to design an API.

**Value — honest limits.** A worker receipt proves delivered bytes, not comprehension. A vendor
may lose history, omit final usage or expose insufficient lifecycle evidence. Instar retains the
work, declared observation gap and worst-case exposure; it does not certify an unobservable path.
Independent OS custody has a stated administrator threat boundary, not immunity to a host
administrator. The native adapter has the same limits and floors as any other worker.

**Rule — design readiness grants no runtime authority.** Rules 26/34/62/65/82/90/109/115;
checks P13-NF-02/43–48. This document awaits joint independent review. No deployment, live test,
convergence, approval or implementation completion is claimed. Activation requires the actual
public-path suite and real conversation evidence for the exact tuple. A constitutional question
cannot be waived by a design reviewer, a successful test or a configuration flag.
