## 4. Launching a worker for durable work

**Rule — durable work precedes the worker.** Rules 29/47/60/63/68/96;
checks P13-NF-14–18. The conversation owner retains verified input before acknowledging custody.
Five resolves its work identity and candidate step; Six admits the current owner and finite
allocation. Ten persists the immutable launch, and Eight/Six prepare the exact process operation
and one-use claim before the adapter invokes it. The worker begins with loading/observation
access only. Launch evidence binds actual process start, artifact, machine and new incarnation;
a reserved name or successful spawn call is insufficient. An uncertain launch is reconciled by
its original operation, never repeated under a fresh name to bypass deduplication.

**Rule — grounding is a real read and a real delivery.** Rules 26/47/68/84/96/110;
checks P13-NF-14/16/17/18/23. Inside Five's `ground()`-invoked read, the host reads current time,
conversation history or fresh covered summaries plus recent messages, identity and governing
briefing, current capabilities, directives, work and uncertain effects. It records the exact
context manifest. Eight/Six admit the loading delivery and claim; Ten records its immutable
`ContextDeliverySpecification` binding those identities, the candidate work and launch. The
adapter delivers once and reports the instrumented context-boundary evidence. Five records
`SessionGrounding` and separately admits the work transition before ordinary effects can run.
The worker may prepare the request context before model dispatch; it need not spend on a model
call to prove that its input was prepared. The actual clock read is never retimestamped.

This uses the existing current-context record and owner doors, rather than a second launch for
every message. Each new input refreshes the current context through the same delivery path.
Unchanged history can be represented by owner-verified coverage; copying the whole transcript
on every input is not required. A vendor cache is never the sole evidence of that coverage.
Opaque hidden context must be declared; a terminal echo or instruction saying “read this” is
not a consumption witness, nor does any receipt prove understanding.

**Rule — cuts retain one attempt.** Rules 26/42/55/63/68; checks P13-NF-14/17/19/24.
A cut before invocation resumes preparation around the same recorded identities. A cut after
invocation observes the original claim and process/delivery before acting again. A cut after
grounding but before the start transition revalidates current history, ownership and grounding;
it does not create a second candidate step. A newly arrived message remains in durable intake;
it neither vanishes nor silently alters the input whose digest was admitted. Ordinary tool,
provider and send doors reject work until its grounding and start are admitted.

**Value — a session's useful lifetime is bounded, not one message long.** Keep a healthy worker
across messages within its allocation. On exhaustion, record unfinished work and admit a fresh
bounded continuation under the same conversation and parent limits. One fresh worker per
scheduled job can remain a scheduling choice; it is not the definition of a conversation.
