## Quiescence, stated before the code changed

The runner's step boundary is `prepareAdmission` (tests/preview/journal-agent.mjs 2768-2771: `mountVolume(identity)` before every step; "Each step is fresh and the port permits only one in flight", 2751-2753). The runner never detaches the volume (detachSessionVolume is a test's cleanup, tool-turn.mjs comment), so a full image stays mounted across launches and a continuing session's harness process keeps its working directory on it between steps. The only owner-independent proof that no process holds the volume is the kernel's: a non-forced `hdiutil detach` succeeds only when no process has an open file or working directory on it, and refuses otherwise. The growth therefore uses exactly that: it attempts a non-forced detach at the boundary and treats a refusal as "a process still holds it", leaving the volume mounted and full and never forcing anything; no pid is read, so absence is never assumed from one process. A continuing session that is alive refuses its own growth until it closes (the measured session closed 08:46:25; the next boundary that reattaches its image grows it).
