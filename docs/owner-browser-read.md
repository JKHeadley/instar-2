# Owner-executed GitHub profile read

Continuing conversation sessions advertise `owner_github.observe` through the existing MCP connector transport. Its only input is `{"page":"account-profile"}`. The owner maps that page to `https://github.com/settings/profile` in the already-running normal Chrome profile for the agent-owned EchoOfDawn account. This does not launch a browser, change a login preference, or grant access to the operator's account.

The worker receives `observed` with page, account, observation time, bounded title and truncation flag, or `login-required`, `refused`, or `unavailable`. These are page observations, not instructions. No cookies, browser handles, profile paths, process ids, page HTML, form values, body text or raw automation errors are returned.

The installation owner supplies `owner-browser.json` beside the runner's existing root configuration. It is a binding, not an authorization store. Its exact fields are `profileId: "echoofdawn-github"`, `service: "github"`, `account: "EchoOfDawn"`, `ownership: "agent"`, and `userDataDir`: the canonical absolute directory of that agent's normal Chrome profile. There is no default directory. The directory must already exist, contain no whitespace, and match exactly one Chrome main process running as the owner. Never point it at an operator profile. The owner config must remain outside the worker's writable/readable scope, like the existing effect policy and custody configuration.

The existing effect policy must have an exact `tool:mcp` registration targeting `mcp__owner_github__observe`, with `consequence: "data"`, `reversibility: "reversible"`, `reach: "agent"`, `costUsd: 0`, and its recorded `source`. It must also have a current grant with that exact effect and target, `approves: ["scope"]`, and the existing required `id`, `source`, `custodian`, `recovery` and optional `expiresAt`. The fixed target binds this grant to the one EchoOfDawn page. A broad MCP grant or an ordinary `reads` entry cannot substitute. Removing or expiring the grant prevents dispatch and withholds an in-flight result.

The current conversation claim's effect owner records the exact input, current policy and owner binding before dispatch. It reuses the existing durable prepared identity to refuse duplicate delivery. Hook admission permits the thin client only; execution and observation belong to the owner checkpoint. A forged hook post cannot complete an owner operation. A failure after preparation remains uncertain in the existing effect record and is never replayed under that identity.

The operation shares the claim's existing call ceiling, deadline, stop, activation and conversation-owner checks. It reserves host maintenance capacity before starting, runs at most one browser read per owner adapter, and allows no more owner requests than the claim's call allowance. Browser work has a 15-second overall deadline, at most 40 fixed evaluations, 250 ms between loading observations, and 2.5-second helper timeouts. A stop cancels only the operation's own helper; it never kills Chrome. Process-table output is capped at 2 MiB and each Apple Event response at 4 KiB. The returned title is at most 256 characters and passes owner redaction and the existing held-secret check before release. The read makes no paid provider call.

The adapter uses the PID-addressed Apple Event implementation from Instar 1.x. Its fixed DOM read checks the exact GitHub origin/path and authenticated `user-login` meta field in the same evaluation as the title. A mention of EchoOfDawn in page text is insufficient. Signed-out pages return no content; another authenticated account refuses. Navigation is fixed to the profile page and never accepts a worker URL or script.

The protected hook installer hashes and installs the thin client and its small contract with the hook's existing support files, so existing installations refresh through the same installation path. The privileged adapter stays owner-side. The capability description comes from the MCP tool list and is available on every continuing-session harness through its existing connector configuration.

The browser is deliberately machine-local. A non-owning or closed claim cannot read it; no other machine launches a replacement. Missing binding, normal Chrome, Automation permission or macOS support returns `unavailable`. The Studio desk owns actual macOS browser proof and the live-group test. Local tests demonstrate request/grant/claim enforcement and replay captured journal shapes; they do not claim a live Chrome result from WSL.
