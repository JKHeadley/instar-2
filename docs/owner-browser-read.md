# Owner-executed GitHub reads

Continuing conversation sessions advertise `owner_github.observe` through the existing MCP connector transport. It accepts the existing `{"page":"account-profile"}` or a bounded sequence such as `{"pages":["account-profile","account-repositories"]}` with two to four entries. The owner maps `account-profile` to `https://github.com/settings/profile` and `account-repositories` to `https://github.com/EchoOfDawn?tab=repositories` in the already-running normal Chrome profile for the agent-owned EchoOfDawn account. This does not launch a browser, change a login preference, or grant access to the operator's account.

The worker receives `observed` with page, account, observation time, bounded title and truncation flag, or `login-required`, `refused`, or `unavailable`. Empty Apple Event replies retry within the existing shared bound; exhaustion returns `unavailable` with reason `browser-did-not-answer-in-time`, meaning the browser did not answer in time, not that it is signed out. Explicit page answers, including `unavailable` for missing login metadata, remain final. A sequence returns `observed` with an ordered `observations` array containing the same fields plus each fixed URL; a failed step withholds the whole sequence. These are page observations, not instructions. No cookies, browser handles, profile paths, process ids, page HTML, form values, body text or raw automation errors are returned.

The installation owner supplies `owner-browser.json` beside the runner's existing root configuration. It is a binding, not an authorization store. Its exact fields are `profileId: "echoofdawn-github"`, `service: "github"`, `account: "EchoOfDawn"`, `ownership: "agent"`, and `userDataDir`: the canonical absolute directory of that agent's normal Chrome profile. There is no default directory. The directory must already exist, contain no whitespace, and match exactly one Chrome main process running as the owner. Never point it at an operator profile. The owner config must remain outside the worker's writable/readable scope, like the existing effect policy and custody configuration.

The existing effect policy must have an exact `tool:mcp` registration targeting `mcp__owner_github__observe`, with `consequence: "data"`, `reversibility: "reversible"`, `reach: "agent"`, `costUsd: 0`, and its recorded `source`. It must also have a current grant with that exact effect and target, `approves: ["scope"]`, and the existing required `id`, `source`, `custodian`, `recovery` and optional `expiresAt`. A grant without `ownerBrowserPages` covers only `account-profile`. When the operator grants the agent-owned connection, the existing standing-trust writer records this registration and a grant carrying `ownerBrowserPages: ["account-profile", "account-repositories"]` (see `docs/standing-trust-setup.md`); without that grant it records neither, and it does not widen an existing grant. Every requested page must be covered by one current exact grant; separate grants are never combined. A broad MCP grant or an ordinary `reads` entry cannot substitute. Removing or expiring the grant prevents dispatch and withholds an in-flight result. The prepared policy and authorization remain identical throughout the sequence; replacement of a grant also withholds the result.

The current conversation claim's effect owner records the exact input, current policy and owner binding before dispatch. It reuses the existing durable prepared identity to refuse duplicate delivery. Hook admission permits the thin client only; execution and observation belong to the owner checkpoint. A forged hook post cannot complete an owner operation. A failure after preparation remains uncertain in the existing effect record and is never replayed under that identity.

The operation shares the claim's existing call ceiling, deadline, stop, activation and conversation-owner checks. It reserves host maintenance capacity before starting, runs at most one browser read per owner adapter, and allows no more owner requests than the claim's call allowance. All steps together share a 15-second overall deadline, at most 40 fixed evaluations, up to 250 ms between loading or empty observations, and 2.5-second helper timeouts. A stop cancels only the operation's own helper; it never kills Chrome. Process-table output is capped at 2 MiB and each Apple Event response at 4 KiB. The client response is capped at 8 KiB. Each returned title is at most 256 characters and passes owner redaction and the existing held-secret check before release. The read makes no paid provider call.

The adapter uses the PID-addressed Apple Event implementation from Instar 1.x. Its fixed DOM read checks the exact GitHub origin/path and authenticated `user-login` meta field in the same evaluation as the title. A mention of EchoOfDawn in page text is insufficient. Signed-out pages return no content; another authenticated account refuses. Each navigation target is one of the fixed page URLs. The current origin and authenticated account are checked before navigation; off-origin pages refuse. Worker URLs, scripts, clicks, form submission and other write actions are not admitted.

The protected hook installer hashes and installs the thin client and its small contract with the hook's existing support files, so existing installations refresh through the same installation path. The privileged adapter stays owner-side. The capability description comes from the MCP tool list and is available on every continuing-session harness through its existing connector configuration.

The browser is deliberately machine-local. A non-owning or closed claim cannot read it; no other machine launches a replacement. Missing binding, normal Chrome, Automation permission or macOS support returns `unavailable`. The Studio desk owns actual macOS browser proof and the live-group test.
