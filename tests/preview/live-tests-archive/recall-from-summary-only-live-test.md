# Summary-only recall — supervised live test for Justin

Use the already approved private preview chat after the integration desk lands
this change. Do not change the active runner, journal, caps, provider policy or
invocation policy for this test. Check remaining call, reply and turn headroom
first; if the trial lacks room, use the desk's normal renewal process rather
than raising limits here.

1. In the private chat, give four harmless exact facts on separate turns: a
   color, a dated event with an absolute `YYYY-MM-DD` date and time, a person's
   preference, and an object location. Record the sent messages and exact dates.
2. Continue with ordinary conversation until status shows several newer
   summaries and the first four turns are outside the next answer packet's
   `history`. Ask for all four details. Compare each answer with the original
   messages, including the exact event date and time. Use `inspect --text` on
   that answer packet to confirm the old clauses came through the summary's
   source-linked items rather than recent history or recalled turns.
3. Correct the event date directly in the same chat. After the correction is
   recorded, continue until another summary is committed. Ask again. The answer
   must give the corrected date and must not repeat the old one. Inspect the
   packet and status: the old clause is withheld, and the active item cites the
   correction's operator turn and date.
4. Restart the approved preview through the desk's normal supervised procedure.
   Ask once more and compare the same four facts and corrected date. Record the
   answer, packet source labels, summary frontier, call usage and any hold or
   UNKNOWN outcome. Stop the trial if a floor or cap refuses; an UNKNOWN send
   must not be retried.

Pass only if all four facts and the corrected date are accurate in the live
answers, the old date is absent after correction, and the evidence survives the
restart. A missing item, bad date, stale clause or an answer that relied on a
recalled original is a failed summary-only case; preserve the journal and report
the specific packet evidence to the integration desk.
