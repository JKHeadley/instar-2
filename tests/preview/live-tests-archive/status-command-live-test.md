# Operator status command: supervised live test as Justin

Use the already approved private journal preview as Justin, in its bound private
Telegram chat. Keep the existing bot, grant, activation, root, expiry, limits,
credentials and time zone. Do not create a second runner or edit its journal.
Read the current `status --root /ABSOLUTE/ROOT --time-zone YOUR_ZONE` output first;
record its call, reply, hold and dated counts. Ensure at least two admitted turns
and two replies remain. If they do not, use the already authorized `raise-caps`
procedure before this test.

1. Send `status`. Save the exact PREVIEW reply. It should have six fixed lines:
   date and zone; turns today; held replies and reasons; pending memory decisions;
   next dated item; model attempt allowance, unknown dollar accounting and reply
   allowance. Compare every count with a fresh local `status` read. The Telegram
   reply itself increases the reply count by one; the reply's own turn is already
   in the turn count. The model attempt count should not increase for composing
   the facts. A Jev check may occur, and an uncertain Jev result can consume one
   existing subscription review slot or hold the reply at the call cap.
2. Send `How are you doing?` in the same chat. Confirm the same shape and a new
   turn and reply count. Send `status of the build` and confirm it uses the normal
   model answer path, rather than the fixed command reply.
3. If the journal already has a held reply or a pending memory/date decision,
   check that its reason or count appears. If it has a confirmed future dated
   item, check that the earliest unforgotten item appears. Do not manufacture a
   live hold, correction or dated event solely for this test.
4. Restart the approved preview runner using its normal stop/start procedure.
   Send `status` once more. Confirm counts persist, each command has at most one
   Telegram send intent and receipt, and no old status reply is duplicated.

Record the three replies, before/after local status output, Jev verdict or hold,
and the exact send-intent/receipt counts. A local read after the reply must count
that reply, so compare against the earlier snapshot for its pre-send figures.
This script is a proposed supervised live proof; the branch's offline tests do
not claim that this live Telegram path has run.
