## Closing block

simplestRobustRoute: the required behavior is that a durable work item can run as a full harness session (Claude Code or Codex) that keeps the existing floors: scoped operator authority, the subscription-only sign-in, the host resource owner, the call cap and the stop. The route taken reuses each existing owner instead of adding a policy system: the existing activation-record mechanism (one more framing per doorway, sealed by the same authority) is the grant; the existing route's auth-status check and the Codex sign-in observation are the per-step sign-in check; the existing resource owner holds the tree through one `hold` method; the journal's existing call allowance takes the edge's reservation exactly as a tool turn's does; the existing driver stop is the kill. Each added piece prevents a named failure the simpler route cannot: the session grant, because the tool grant admits a confined turn (and the Codex doorway serves none) while this path is unconfined; the transcript meter, because neither harness's interactive session has a turn cap and the Codex TUI has no per-call hook, so one obligation debit bounded nothing; `hold`, because tmux, not the owner, forks the session; the stop-before-close, because returning first left the child running (reproduced); the operation-derived claim, because a shared claim made every second item need a continuation nobody supplies. Rejected: wiring the tool grant (no Codex route, wrong authority), a second limiter, a per-harness hook meter, and supplying a continuation provider for independent steps.
