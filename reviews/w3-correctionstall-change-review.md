## Closing block

simplestRobustRoute: the required outcome is that a verified operator's correction is never left with no reply and no attempt. The simplest robust route through existing mechanisms is to extend the existing settle that already handles a summary which cannot reach the request (`settleExhaustedEdit`) by the one state it missed, a preflight refusal, which the summary path already records durably as a hold; and to let the request's own answer run as it already does for undecided corrections. This proposal is that route: one predicate in the settle, one hold release for the request it settles. No new ledger, row kind, classifier, review layer, retry or flag.
80/20: 0 must-fix, 2 notes — (1) the rolling summary frontier on such a root stays stuck: later corrections are decided by their answers and later replies are prepared from summary-plus-recent history with the existing floor, but the summary no longer improves; that is the next repair, reported separately; (2) a cancel decided by the answer rather than the summary leaves the correction recorded undecided, so a request made before it that the answer did not cancel stays held, which is the existing conservative rule.
VERDICT: author submission; the independent verdict is recorded as a pass
