# Change review — session-volume-parity-1105: bounded growth of the delegated session volume

Subject base: a8f354e1b3aa6497624afdcc1c31426a8b5d257e

Reviewed content: none
Outcome: The delegated session's working scope (tests/preview/tool-turn.mjs attachSessionVolume) was created at 2 GiB and only ever reattached, so one whole-repository session (measured 2026-11-05 on update 969390679: a 1.09 GiB checkout plus 0.67 GiB of temporaries, 0 bytes free) filled it with no way out. ## Closing block

simplestRobustRoute: the required outcome is that a session whose volume filled can continue without a new root while the host storage bound holds. The simplest robust route is growth at the one existing boundary in the one owning function with the already-proved resize primitive, bounded by a constant and the host's measured free space, with quiescence proved by the kernel's refusal to detach a held volume; that is this change. Added machinery: none beyond one function and one constant; the failures it prevents are the measured full volume and the forced unmount of a live worker (which the non-forced detach cannot do). Not chosen: a growth watcher (notices after the bytes exist), a new journal field (no new schema), moving sessions onto a larger fixed size (another arbitrary cap without headroom), or a per-root policy value (not needed for the repair; the constant can become one later at the same call site). Start guard: the existing boundary; end guards: the five native cases and the register check; limit guards: the bound, the host reserve and the five floors. No unattended live completion is claimed.
