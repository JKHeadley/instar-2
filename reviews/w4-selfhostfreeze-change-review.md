Outcome: the shipped self-host command could not reach its own registered model doorway. `tests/preview/self-host.mjs` main() loaded `--login-profile` with a plain `JSON.parse`, and the provider credential custodian (`src/assembly/provider-credential-custodian.ts:78`) admits only a frozen host-owned descriptor, so the route was refused inside the route factory and the command exited "self-host refused: preview: subscription route refused" with zero provider calls. Rule 2's and Rule 115's J5b-d therefore passed only through the desk driver (`j5-driver=desk`), never the CLI. This change freezes the parsed descriptor at that one loading point — the same shape `tests/preview/journal-agent.mjs` and `tests/preview/agent.mjs` already load it in — and leaves the custodian exactly as it was. A new test runs the real command with the doorway's captured-frame conformance fixture as its physical IO: before the change it ends with the custody refusal and zero provider calls; after it, the doorway is called once and its answer is recorded, and a login descriptor the activation does not name is still refused with zero calls. A second test states both arms of the custodian's own frozen-descriptor check, so a later reader cannot mistake this repair for loosening it.

## Closing block

simplestRobustRoute: the required outcome is that the shipped self-host command reaches its own registered doorway without weakening provider custody. The simplest robust route is to freeze the descriptor where the command already parses it — one expression, matching what the sibling commands in this tree do — and that is this proposal. Alternatives considered and rejected: (a) relaxing the custodian to accept a mutable descriptor, which would delete the guarantee that an admitted route cannot have its binding changed underneath it; (b) having the custodian freeze the descriptor itself, which hides a caller's mistake and leaves the caller's own copy mutable; (c) leaving the desk driver as the permanent path, which is precisely the gap Rule 115 names — a reference client that cannot do the work is not the reference client. No machinery is added, so no added-machinery justification is owed; the applicable guards are the existing ones (the stop latch before the doorway is built, the attempt allowance, the activation expiry) and they are unchanged. The autonomous-completion claim for Rule 115 is NOT made here: the unattended shipped-path result is the live-proof J5 run with `j5-driver=cli`, which runs on the Studio.
