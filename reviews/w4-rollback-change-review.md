Rehearsed 2026-10-04 00:03 and reproduced here with the two real builds: cint-L45 wrote a root, cint-L44 refused to start on it, so rolling the operator's preview back one build would have cost his conversation memory. The cause is one line. `project` in tests/preview/journal.ts ran its whole kind chain and then fell through to `const turn = view.turns.get(row.id); if (!turn) throw Error('preview journal: orphan effect')` (cint-L44 journal.ts:3116, the same line at journal.ts:3737 on cint-L50), so a frame kind the reader had never heard of — which carries no `row.id` — was diagnosed as an effect whose turn was missing, and the ENTIRE root was refused before status and before any mutation. There is no journal format or schema version anywhere; the frame-kind union IS the schema, and the three kinds cint-L45 added (`session-work`, `retro-duty-reserve`, `retro-duty`) were enough to make the root unreadable. This change splits that fall-through. A kind this build does not project is now told apart from an orphan effect and admitted on the frame's OWN declaration: `forward: { generation, additive: true }` means a reader that skips it still holds a correct, if less complete, projection, and one such generation ahead of `JOURNAL_GENERATION` is read and served. Two generations ahead is refused, loudly, naming the generation. An unknown kind that declares nothing is still refused — it may be load-bearing — now named `unknown frame kind` instead of misreported. And an older build will not compact a root carrying a frame it skipped, because compaction replaces the frames with this build's projection, which does not contain them; it keeps reading, answering and appending, and refuses only the rewrite.

## Closing block

simplestRobustRoute: the required outcome is that a root a newer build has used stays readable AND runnable by one build back, without weakening any integrity check, and that a root further ahead is still refused loudly with its reason. The simplest robust route through existing mechanisms is what is built: the journal already keeps unknown FIELDS (`project` reads only the fields it names, and `restoreSnapshot` carries unknown saved fields through `{ ...saved }`), so the only thing missing was that an unknown KIND was misdiagnosed. One early branch in the one function every frame passes through, one generation number, one named set of kinds, and one predicate on the two existing compaction call sites. Nothing new is stored, no file is added to a root, no record changes shape, and the projection digest is unchanged. Two simpler routes were considered and rejected, each recorded above as a decision: a down-step per migration (the older build cannot run code it does not have, so it needs an operator step a crash-switch skips) and skipping every unknown kind unconditionally (it swallows a load-bearing frame in silence, which is the failure the window exists to prevent). The added machinery prevents a named, credible, already-observed failure: on 2026-10-04 00:03 an older build refused a root outright, which would have cost the operator his conversation. The guards are the generation window (start and limit), the additive declaration (the admission test), and the compaction predicate (the end-state protection); all three are proved on both sides in tests/preview/journal-rollback-window.test.ts. No agent, skill, service or store is added.
