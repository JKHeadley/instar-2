## Closing block

simplestRobustRoute: the required outcome is that a summary pass can always run and advance the frontier by at least one turn on any root whose turns fit the per-message bound. The carried summary already has hard accept bounds (8192 bytes of prose, 20 memory items of 300 bytes), so the simplest robust route is to size the summary prompt ceiling to hold those bounds, the fixed parts and one maximum turn, scaled with the context limit as the 24 KiB ceiling was with the old 32 KiB one, and to stop an UNKNOWN frontier from flooring other spans while keeping it reserved and never re-dispatched. This proposal is that route: one constant becomes a function of the limit and one floor is removed. No new retry layer, ledger, classifier, review step, compaction step or flag. Start guard: the unchanged 24 KiB start threshold. End-state guard: the frontier reaches the last turn (replayed). Limit guards: the existing call cap, eight-attempt pass, four-turn span and recovery pause.
80/20: 0 must-fix, 2 notes — (1) a correction sent while a long backlog is still being caught up waits for the summary to reach it, as on any root whose frontier is behind; on Justin's root that can be up to about 80 summary calls once, until the catch-up completes; (2) earlier patches on this path now unnecessary on the live roots (over-bound turns aside) are listed in the PROGRESS record for a later Occam cut; none is removed here.
