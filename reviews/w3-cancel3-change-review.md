## Closing block

simplestRobustRoute: the required outcome is that "cancel my <reminder>" is recorded as a cancellation, named in the reply, and leaves the other request to fire. The cancel decision that does exactly that already exists on the answer path and passed live twice; it failed here only because a summary forget had already removed the request before the answer saw it. The simplest robust route is to stop a forget from ending an open request, so the request reaches the cancel decision. This proposal is that route: one guard in the existing memory validator. No new field, row, model call, prompt text, retry or flag. Start guard: only a forget whose target message carries an open, unsent request with an overlapping quote is affected. End-state guard: the existing quote check decides whether anything is cancelled, and a request not withdrawn still falls due once (replayed). Limit guards: the existing citation and quote bounds and the unchanged reply and call caps.
80/20: 0 must-fix, 2 notes — (1) an explicit "forget my <open reminder>" cancels it (when the answer reads it so) but keeps its text until a later forget; (2) a failed answer on a later operator turn holds earlier requests without bound (decision cancel3-leave-the-failed-answer-hold), reported to the desk.
