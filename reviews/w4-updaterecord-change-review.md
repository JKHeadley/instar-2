## Closing block

simplestRobustRoute: the required outcome is that a root relaunched in place onto a new build records from = the previous launch's revision and at = this install time, so rule 44's live check J1e names the first reply after the switch, with the fresh-genesis and same-build cases unchanged. The record is already derived in one function from one predicate, so the whole route is that predicate: add the revision to the sameness test, with an unknown revision falling back to the digests. That is this proposal. The one addition beyond it is the exported staleAgainst helper, which is not new machinery but the removal of a duplicated comparison: the identical blind spot sat in two inline copies of the digest test, and the named credible failure it prevents is a process reporting "running code matches the installed files" after its checkout was switched under it — the exact case the module's docstring claims is visible, and the case a byte-identical closure hides. Alternatives considered and rejected: (a) widening RUNNER_EXECUTED_ENTRIES or the closure so the digest covers every shipped file — the digest answers "what bytes does this process execute", which the stale check and the bridge/loader cases depend on, and every docs commit would then read as changed executed code; (b) keying the record on the revision alone — loses the two cases the closure exists for, executed code outside the import graph and a checkout with no readable revision; (c) recording the previous revision on the launch row at launch time — a new durable field for a fact the rows already carry, and it would not repair the roots already running; (d) relaxing J1e to accept an older reply — forbidden by the brief and wrong, since the check is right and the record was wrong.
