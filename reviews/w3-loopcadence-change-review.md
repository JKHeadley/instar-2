# Change review — w3-loopcadence: the open-loop revisit interval becomes a per-root value set at genesis

Subject base: 4addcb0689d10ff4e0b96863079d0a36f80419a2
Review state: open
Reviewed content: none
Outcome: Plan row #313 (observer note #132). Seven rules (8, 22, 46, 64, 92, 97, 102) are proven live only by proof group D, and D's second half needs an open loop's revisit to come due with no inbound message. That interval was the hard-coded `LOOP_REVISIT_MS = 24 * 3_600_000` in tests/preview/journal.ts, so each live proof cost a real day and a failed setup wasted the whole day. No rule requires a literal day: Rule 8 says an open loop is "re-surfaced on a schedule" and Rule 92 says a cadence is "adjustable per session". The interval is now a value the root's genesis records (`loopRevisitMs`), read through one accessor `loopRevisitMs(view)` by every scheduling and due computation; absent means the unchanged 24-hour default. It is set only at genesis, by `--loop-revisit-minutes N` on the launch, bounded at 10 minutes to 24 hours, and no later launch or command can move it. Status reports it as `obligations.revisitMinutes` so the proof script reads the root's real interval instead of assuming one. A proof root launched at 15 minutes proves the same behaviour in minutes.
Affected rules: 2, 8, 46, 64, 92, 97, 102, 116 (2 — nothing is lost: the interval is journaled in genesis, so it survives restart, snapshot reopen and a second machine, and a root that names none keeps the default; a root written by the base build is read unchanged, proven against a journal that build wrote; 8 — the floor "re-surfaced on a schedule" is kept: a root may bring its loops back sooner than a day, never later, which is why the upper bound is the default itself; 46, 64, 92 — the backlog, throughput and cadence surfaces all read the same per-root value through one accessor, so none of them can disagree with the scheduler; 97, 102 — unchanged: the interval decides only when a scheduled step is due, never whether a run may stop or who decides; 116 — one optional genesis field, one accessor, one launch option; no registry, no change path, no new row kind, no state beside the journal)
Affected floors: secrets — unchanged (the interval is a duration, no text leaves the machine, and nothing model-facing changes); spend cap — a shorter interval makes an open loop's scheduled steps come round sooner, so a 15-minute root can spend its model-call allowance faster; the allowance itself, its cap check and the reply reserve are untouched, so the cap still binds exactly as before and a root that exhausts it is inhibited as before. The lower bound of 10 minutes is there for this reason and the default is unchanged, so no existing root's spend changes at all; stop — unchanged (the same gate runs before every attempt and send); no duplicate sends — unchanged: the reply-only grant, the bound-report rule and the receipt settle are untouched, and the test exercises the work step and its awaiting-delivery state; durable intake — unchanged: no record kind is added and no existing field changes meaning; one optional field joins the genesis record, which is written once and read back byte-identically by the snapshot comparison.

## Closing block

simplestRobustRoute: the required outcome is that group D's second half can be proven in minutes rather than a day, without weakening Rule 8. The simplest robust route through existing mechanisms is to move the one number the wait depends on out of the source and into the place a root already records its own fixed parameters — its genesis, which is written once, journaled, compared byte for byte by the snapshot restore, and has no other writer — and to read it through one accessor. This proposal is that route: one optional genesis field, one accessor, five call sites, one launch option with bounds, one status number. No registry, no change-path authority, no new record kind, no flag, no state beside the journal. The simpler route still available — leave the constant and shorten it in the source for a proof run — was rejected because it changes the live runner's cadence too and cannot be proven to leave existing roots alone.
80/20: 0 must-fix, 2 notes — (1) a root created with a short interval spends its model-call allowance faster, which is the point and is bounded by the existing cap; the ten-minute floor is what keeps that from being unreasonable; (2) the migration doorway gives a migrated root the default rather than carrying an interval over, which is correct today because no pre-journal store has one, and would need revisiting if a migration ever starts from a journal that does.
