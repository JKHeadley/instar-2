# Change review — w3-correctionwedge: an unfinishable memory correction holds only itself, never every later turn

Subject base: 055486b055ea5beaa00fd6787ab2c80e0bb6db5d

Outcome: On the proof room of 2026-10-01 (room two, proofroom2-small, 32,768-byte context, 18:40-19:02 PDT, live build L19s 51dab1e0) one memory correction left every later turn unanswered: notes 1 and 2 were answered, note 3 (update 6230417) was held with reasons ["memory correction pending", "summary faithfulness: stale corrected or forgotten claim"], and notes 4-9 were accepted as turns and never answered (turns 9, replies 2, obligations.unansweredTurns 6, inhibition "held: summary faithfulness: stale corrected or forgotten claim", reply-3.json .. reply-7.json empty). Cause: the reserve squeeze dropped the memory candidates from the packet (packet.dropped, two `candidate` rows), so the model's own memory update could not be validated against one and the turn became a request only the rolling summary could decide; the summary then restated the already-corrected clause, so the faithfulness check refused it (modelFailureClasses {malformed: 7} over nine summary calls, summaryThrough still 6230414). A `summary faithfulness:` hold is released only by an accepted summary covering the turn, so the refusal that set the hold was also what made its release impossible — a latch, not a wait, and nothing else could clear it. Fix: in the `summary-failed` projection, once a frontier has used its two retries (so no summary at it can ever be accepted and the release condition is unreachable), every turn held with a `summary faithfulness:` reason at or before that frontier is released to the ordinary answer path. The refusal itself is unchanged: the candidate is still rejected and never committed, and the packet still projects the corrected clause as withheld. Evidence: tests/preview/journal-correction-faithfulness-wedge.test.ts (3 tests; all three fail on 055486b0 and pass here) replays the recorded message texts and the recorded summary shape through the real worker at a scaled reserve squeeze, asserts the recorded preconditions (a dropped `candidate`, the recorded failure reason, no accepted summary, an exhausted frontier) before asserting that all nine turns are answered with no inhibition, that no packet built after the correction landed carries the stale clause, that one refusal still holds its frontier turn, and that a journal the live build already wedged recovers on the next drain and replays the same release from its own rows. A later commit (5671d620) adds the third property the unit owes and had only argued: the operator is told nothing false about the correction that did not land — a turn settled undecided never sends a "Changed X -> Y" claim (it sends the fixed MEMORY_UNDECIDED_REPLY), and every change claim that is sent names a replacement `view.memory` actually holds, with a counter guarding that clause against going vacuous (the delivered arrow is U+2192). That property already held on the existing machinery, so the commit adds assertions only, no source change.
