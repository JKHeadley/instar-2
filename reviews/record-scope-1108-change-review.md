# Change review — record scope: a record answers only for text its own commits wrote

Outcome: scripts/check-change-review.mjs no longer asks an older change-review record for Prompt finding, Deferral or Skip lines covering text it never changed. Re-editing an older record moves its last commit, so its base..last range came to span later merges; the tree diff then gave it every merged input's deferral and skip lines, and its widened subject gave it every finding in those files. Three merges were refused for this in one night (train-209: 10 lines over two records, train-211: 11, train-216: 51). Now a Deferral/Skip hit with no row of its own is not demanded when git blame at the record's last commit names a commit that an earlier valid record covers, meaning a record whose last edit lies strictly inside this record's range. A prompt finding outside the files the current change touches is not demanded of a changed record when the finding was already present at the record's own base, or when an earlier record in range carries a valid disposition for it. Everything else is unchanged: the record's own lines (new or original), findings in files the current change touches, the Prompt review requirement, Rule 102 decisions and frozen subjects. 1.x comparison, from JKHeadley/instar main 5bcc9c87a5ff755104855c5458a479e427146e8b: scripts/instar-dev-precommit.js skips its gate for merge commits (Step 0, MERGE_HEAD) and scopes every check to the commit's own staged diff (`git diff --cached`); scripts/lint-deferral-carrier-resolvable.mjs ratchets only newly added deferral markers from the same staged diff. So 1.x answers per commit for its own added lines, and merged text is never judged again. 2.0 checks whole record ranges after the fact, so the equivalent here is the per-line blame and earlier-record rule; the 1.x per-commit hook shape does not fit a range-based record and is not copied.
