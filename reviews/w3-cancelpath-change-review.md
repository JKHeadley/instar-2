## Closing block

simplestRobustRoute: the required outcome is that a message withdrawing a requested action is decided by the answer turn that reads it, that a withdrawal the model could not carry out leaves the requests open and says so naming them, and that no request stays held for good by an undecided earlier message. The answer turn is already handed the open requests and the quoted cancelReminders contract, and the summary row already stores "withdrew nothing" as the empty array, so the simplest robust route is to record the answer's verdict in that same shape, stop the two fixed memory lines from replacing a reply that carries it, name the standing requests in the two cases where nothing was withdrawn, and bound the existing wait by that turn's own reply. This proposal is that route: five edits in one file, all on existing fields and sentences. No new classifier, keyword rule, ledger, retry layer, review step or flag; the memory cue, the quote check, the due-turn grouping and the notice's own case are left as they are. Start guard: the packet offers open requests only when some are open, so a conversation with none is byte-identical. End-state guard: the admitted cancel removes the request from the open set, and the requests it did not name fall due once (replayed). Limit guards: the existing ten-citation bound and quote-length bounds, the three-request naming bound with its "and N more" count, REQUEST_ITEM_LIMIT on the grouped due turn, and the unchanged reply and call caps.
80/20: 0 must-fix, 3 notes — (1) an answer that returns no cancelReminders field at all on a turn with open requests still gets the fixed notice, so the operator is told to resend; the requests survive and fire, and the packet now asks the model for the field explicitly, but a model that omits it still produces that reply; (2) a request released by the bounded wait that is already past its minute fires late rather than at its time, which is the open direction Rule 95 declares for reachability and is stated under the existing "you asked on" header; (3) the memory cue still sends a withdrawal to a summary decision that cannot answer it, so two summary attempts are still spent on the way (decision cancelpath-leave-the-summary-routing-alone).
