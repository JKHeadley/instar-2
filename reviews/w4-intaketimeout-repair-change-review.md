## Closing block

simplestRobustRoute: the required outcome is unchanged — a test child that blocks forever must fail its own test quickly and legibly instead of freezing a whole gate run, for every synchronous child call rather than the one that happened to hang. What changed is which route delivers it most cheaply. The route taken is three public wrappers plus one supported publish call: `spawnSync`, `execFileSync` and `execSync` are replaced on `node:child_process` and `syncBuiltinESMExports()` republishes them, so every import style a test can write resolves the wrapper. Everything that previously justified going lower is removed with it: the deprecated `process.binding`, the libuv negative-errno comparison, and the guard written to make that binding's eventual removal loud. The cost of the public route is that three exports are wrapped where one binding sufficed — about ten lines, each a published contract — and the benefit is that none of the three contracts is deprecated or internal, so nothing here can go quiet under a future Node. The 202-hand-edits route is still rejected for the same unchanged reason: it cannot be verified inside this unit and is silent for every future callsite. The machinery kept beyond the injection is the stderr line, whose named failure is a hung case reported only as a bare "Test timed out in Nms" with no indication that a child blocked — the diagnostic gap that cost 54 minutes. Guards: the start guard is that the doorway acts only inside a vitest worker (installed by `setupFiles`, never by product code) and only on a call that named no `timeout`, so a caller-owned bound and every non-test process are untouched. The end-state guard is that the child is dead (SIGKILL) and the call raises `ETIMEDOUT` with the explanation also on stderr, and that the patch is idempotent behind `Symbol.for('instar.tests.boundChildren')` — asserted on the module and on each wrapper — so a re-import cannot double-wrap and cannot republish twice. The limit guard is the bound itself: the case's own declared timeout, or the finite 300 s collection-time fallback, with `INSTAR_TEST_CHILD_BOUND_MS` the only widening knob and no path to an unbounded wait except a callsite deliberately writing `timeout: 0`.
