MUST-FIX 1: the withheld-result route added in w4-d1c repair 1 kept the correction input (the rejected report verbatim plus the review's objection) only across an `uncertain` result. A `failed` result — a provider failure, or an answer that is not a decision — supplies no corrected report either, yet it was projected as an ordinary result, so `withheld` was dropped by an attempt that answered nothing. The next packet then carried neither the rejected report nor the objection, and the step regenerated the same rejected report; the state survived journal reopen (the review's injected-failure probe: `firstAttempt: failed`, `retryHasObjection: false`, `regeneratedRejectedReport: true`, `awaitingDelivery: 1`). Fix at the source: `failed` is the same class as `uncertain` — no account of the work — so one predicate, `noAccount(outcome)`, now states that once and both the projection and the rework schedule consult it. The correction input is retained until a step actually answers it, and a failed attempt's retry waits the revisit cadence instead of being due at once (preserving the input alone would leave failed rework immediately due and permit a tight retry cycle, which the reviewer named). Nothing else changes: a `report`, `continue` or `waiting` result still clears `withheld`, and settlement still requires a sent receipt for the full text.
