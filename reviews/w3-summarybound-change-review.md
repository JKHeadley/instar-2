## Closing block

simplestRobustRoute: the required outcome is that a summary call that must be accepted always fits its output cap, and that a base which cannot fit stops spending. The simplest robust route is to derive the one bound the code accepts on re-emitted content (the prose) from the cap that already exists, ask the model for that and for short reasoning, and turn the existing over-cap ceiling into a brake instead of releasing it, with one recorded field so a changed build is a changed input. Raising the cap was not taken: it is part of the activation-bound invocation policy and a spend decision. Cutting the span lists was not taken: they shrink with the span and the existing cascade already shrinks the span. No retry layer, ledger, flag or new row kind; the whole-answer bound was built, measured against a real answer, and removed.
