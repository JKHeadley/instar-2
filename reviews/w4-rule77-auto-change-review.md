## Closing block

simplestRobustRoute: the required outcome is that an operator's plain question is answered in the pass that exhausts the summary frontier, rather than a pass or more later. The simplest robust route is to let the existing exhaustion settle drain: loop it over the pending requests so every request that frontier has already exhausted is settled in the one pass, reusing the existing `memory-undecided` record, the existing `summary-failed` reason and the byte-identical predicate — the same shape `settleBehind` beside it already has. This proposal is that route, and it is strictly smaller than round 1's, which added a second predicate and left the real one one pass behind. Alternatives considered and rejected: (a) bounding the "earlier turn pending" ordering hold by a timer — treats the symptom and puts a clock-dependent release at the centre of the correction discipline; (b) making a held turn eligible for the minimal responder — delivers a truthful limited reply inside the floor but leaves the ordinary answer a pass late; (c) widening `summaryFormatFailures` to survive an accepted summary — changes what "exhausted under the current format" means for every other consumer, and is not needed because the counter already reached 2 in the recorded sequence; (d) keeping round 1's `settlePassedFrontier` beside this fix — rejected above, no named failure the drained settle cannot handle. No added machinery: no new record kind, store, prompt, gate, model call or predicate, and one predicate removed.
80/20: 0 must-fix, 3 notes. (a) `memoryHealthLine` counts a `memoryUndecided` turn as an unresolved correction, so the operator surface over-reports; recorded as a decision above and left to its own unit. (b) `limitedReason` still returns null for any held turn, so while a request is genuinely and reachably pending its own reply can still pass the 120 s floor with only its held notice; that is the designed held-notice path and a separate unit if the floor is to cover held turns. (c) The live root's summary frontier was failing `malformed` repeatedly (37 of 52 summary calls); this change stops that failure from costing the answer path an extra pass, but the malformed summary reading itself is a separate defect class and is not touched here.
