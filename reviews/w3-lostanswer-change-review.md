(1) "Where did I say I keep the extra thing that unlocks the hut in the woods?" (update 6230861) was answered "I lost my answer to that message. Please send it again." Its first answer call returned a lookup request, not an answer: the malformed count is 9 before and after the turn, so it was not a format re-ask, and the second call's prompt is 779 bytes larger, which is the lookup packet. No usable earlier answer was discarded, because there was none; what was lost was a question the journal could still answer. The same 120 s hang ended group A 6230665 (a first call) and S 6230832 (a first call, answerMs 122247), so it is a product path, not a build-switch artefact. (2) "What name did I give you for my sister's horse?" Fixed: an answer call whose own recorded physical outcome is the local timeout with confirmed cleanup is replaced once, on the same packet, under the same call cap, while the timed-out call stays UNKNOWN and charged under its own key; a turn whose model ran its one lookup keeps its own reply when it also sets memoryList; inspect projects memoryLookup. ## Closing block

simplestRobustRoute: the required outcome is that a question the journal can still answer is answered rather than ending in "send it again", and that a never-said question gets the honest searched-and-not-found answer. The simplest robust route through existing mechanisms is: read the launcher's existing call-outcome row, and when it proves the local timeout ended the call with confirmed cleanup, ask once more on the same packet under the same cap, keeping the old reservation charged (docs/09's replacement); and let the turn's existing lookup record stop the memory-list substitution. This proposal is that route: one row kind with one reducer, one helper reading an existing row, and one extra condition on an existing branch, plus one inspect field. No new port field, classifier, timer, backoff layer, flag or wording. Start guard: no replacement unless this turn's latest model call-outcome row is a timeout with verified or unconfined cleanup, the turn has no outcome and no intent, and the cap leaves room including the reply check's slot. End-state guard: the replacement's result is settled by the existing format re-ask, lookup and answer paths, and a second UNKNOWN ends in the existing notice. Limit guards: one replacement per turn (answerReplaced), the existing call cap, stop and expiry, and the 120 s call timeout on the replacement itself.
80/20: 0 must-fix, 3 notes — (1) a replaced call that also times out still sends the loss notice, now after about four minutes instead of two; (2) a "what do you remember about me" turn whose model runs a lookup gets the model's own reply rather than the journal-rendered list (not observed; the list path without a lookup is unchanged); (3) a send that settles UNKNOWN still leaves the operator unsure whether the reply arrived, and its recorded reason is not projected by status (decision lostanswer-send-unknown-left-alone).
