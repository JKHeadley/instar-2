## Closing block

simplestRobustRoute: the required outcome is that a reply which delivers a promised item closes that promise, and one that does not never closes it. Both already exist: the packet offers the promise with owner agent and its id, the model declares fulfilled, the answer row records the claim, the intent row records the ids the final text still carries, and the receipt closes them — verified end to end on the recorded packet. The only thing preventing it was that the fulfilment quote was measured against the 500-byte bound written for a promise sentence, so a whole-reply excerpt over that bound discarded a correct declaration. The simplest robust route is to measure it against the reply it must appear in, which is the bound that was always doing the real work. This proposal is that route: one constant and one default parameter, no new field, row, model call, prompt text, retry or flag. Start guard: only a model-proposed fulfilment claim is affected; a promise sentence keeps its own bound. End-state guard: the existing containment and fulfillable rules decide admit versus refuse, identically on the writer and the replay, and a refused claim is still counted. Limit guards: the bound is finite and byte-exact at 4096 (proved on both sides, including a multi-byte boundary), the five-claim cap is unchanged, and the reply cap already bounds any admitted quote.
80/20: 0 must-fix, 2 notes — (1) the second cause above: a model that quotes the promise's own sentence instead of its reply still leaves a delivered promise open, so check A5b can still fail; it needs an ANSWER_PROTOCOL wording that says which text the quote comes from, plus real calls to prove it (decision promiseclose-leave-the-containment-floor-and-report-the-second-cause); (2) a refused fulfilment declaration is visible only as a count (rejectedDeclarations) — nothing names which promise was left open, which is why this defect survived a live run that otherwise passed; reported to the desk rather than fixed here (Rule 116: not needed for this outcome).
