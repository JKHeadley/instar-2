The simplest robust route is to apply the per-row disposition the validator already has (w3-retrolive's "a row that breaks its own rules is dropped") to the one row kind and the one per-duty claim that still refused the whole pass, and to remove one refusal the validator caused itself. No new ledger, retry, row kind, flag or classifier is added. The only new symbols are a note string and the predicate the status line uses to read it. The question gains two sentences only because it and the validator must state one contract. The deeper fix, a duties contract that does not depend on the model counting positions, is named and deliberately not built, because it changes the answer contract beyond this brief. Start guard: the plan, admission and spend cap are unchanged. End state: a completed pass with honest per-duty dispositions. Limit guards: the output cap, the call reserve and the fail direction are unchanged.
