Recall on this path compares word stems; the question and the fact share none, so nothing on the read path could connect them. The first commit (0b5f1315) pinned that in a test replayed from the recorded texts and fixed one indexing defect (a term carrying a clock time cost a message its whole term list). The desk then resolved the reported conflict from Rule 11 and design part 21 (plan row #268): query planning is a subordinate purpose of the live root, bounded by its call budget. This change adds that step. When the packet does not show what the message asks about, the answer model returns only {"lookup":[up to six short phrases]} instead of a reply. The runner searches the summarized turns once with those phrases through the same recall owner as the question, puts what it finds first among `recalled`, and asks once more. The second answer is a reply: it uses what was found, or says it searched and did not find it and that this is not proof it was never said. On the real answer model (claude-sonnet-5, 11 calls, outputs stored verbatim in the fixture) the shipped wording asked for a lookup in 3 of 3 paraphrase calls, each word list retrieves the fact under both real index samples, and the full two-call turn answered 2958. The same model made no lookup when the packet already carried the fact and none for an arithmetic question; for something never said it looked up once, found nothing, and said so.

## Closing block

simplestRobustRoute: the required outcome is that a question which shares no word with a summarized fact still reaches it, without a model call on every turn. The simplest robust route through existing mechanisms is the one the design already names: the answer model, which is the only reader of the question by meaning on this path, asks for a search in its own words, and the existing recall runs it. This proposal is that route. It copies the format re-ask: one journal row, one reducer branch, the same cap and stop checks, and the existing preparation builds the second packet. Added machinery and the failure each part prevents: the `lookup` row (without it the second call would be uncounted and a restart could not tell it happened); the offer marker (without it a root at its cap would be told to ask for a search it cannot run); the fixed runner replies (without them a second or unrunnable request would be sent to the chat as a raw object, or loop); replacing the saved prompt (without it the reply review would judge a found fact as unsourced). Not built: a ranking call on every turn (costs a call per turn for a rare miss), a new store or index, a keyword list, a status counter. Start guard: the offer conditions. End state: a reply, always. Limits: one lookup per turn, six phrases of 80 bytes, five found turns, the call cap, the stop latch. Unattended shipped-path result: the real answer model, through the product's own prepared envelope and the real answer path, asked, the runner searched, and the second call answered 2958 (fixture sample P1); it has not run in a live room.
80/20: 0 must-fix, 5 notes — (1) the lookup depends on the answer model choosing to ask; 3 of 3 on the shipped wording is a small sample, and the benchmark case replays recorded phrases rather than calling a model; (2) the phrases must still share a stem with the stored message, its reply or its terms, so a fact stored in words the model does not guess stays unreached and is disclosed as not found; (3) the 284 always-sent bytes are paid by every root, including ones that never look up; the combine re-measures against cint-L25's guard; (4) the summary's cap of 20 exact fact quotes is unchanged: a 21st fact is not added to the quotes and no row records that; the lookup reaches it through its original message; (5) no status line counts lookups; the row is in the journal and the turn's saved prompt shows the searched phrases.
