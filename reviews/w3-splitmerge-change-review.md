## Closing block

simplestRobustRoute: the required outcome is that a split run still answers the gate's whole-suite questions. The two halves together are the whole suite, so the simplest route is to add the two reports up and let the existing checks read the sum, changing none of them. That is this proposal. Rejected alternatives: teaching each of the eleven checks to union two reports (eleven edits to delicate evidence code, and each would then accept a foreign host's report); relaxing the whole-suite assertions so a half passes (that deletes the coverage guarantee the checks exist for); and running the checks only on the Mac or only on the Linux host (neither half carries the other's test identities, and plan rule 17 forbids making the Studio the only lane). The one piece of added machinery is the `otherHalfFiles` argument on `checkBootRecoveryCoverage`: without it that function cannot pass under any split, because it demands both the whole checkout's file set and a single real main-process exit, and no single process runs the whole suite in a split. It defaults to empty, so unsplit behaviour is unchanged. The merge refuses an unknown report field rather than guessing, which is what keeps "add the two reports up" honest as vitest changes.
