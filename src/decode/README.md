# Part One decoding

The single decoding boundary: `decode.ts` checks every constitutional value (provenance, verified principals, grants, measurements) against its schema and invariants, and `canonical.ts` gives the one canonical byte encoding and hash. `framework.ts` lets later parts register owned decoders. Design: `docs/05-the-types.md` and `docs/06-the-fact-envelope.md`. `explicit-yes.ts` decides, in one place, what counts as an explicit yes behind an `Authorization`: a verified approval record, or an `account-assented` yes (an operator chat reply or operator-account review approval), a provenance class assigned only while its single declaration, `accountAuthenticatedAssent`, is enabled and the explicit-yes producer's sealed admission of that exact record (`admitAccountAssent`, not exported by the package) is in `DecodeContext.accountAssent`; a record label alone stays `channel-attested`, and an `Authorization` refuses an admission that names another request; such a yes never produces a principal. It is enabled since the approval-gesture amendment (PR #139) landed.
