# Fact contracts

Implementation of `docs/06-the-fact-envelope.md`. Imports constitutional values and decoders through the part-one public package entry. The public fact surface is `@instar/constitutional-types/facts`; projections are exposed at `@instar/constitutional-types/projections`.

`envelope.ts` validates canonical content hashes, Ed25519 signatures, key-position windows and origin identity. `admission.ts` selects causal history, checks standing, validates registered body fields through part one, and gates repairs. `contracts.ts` holds only part-two records and named provider ports. `boundary.ts` adapts part one's extension-decoder framework without constructing Result or constitutional values locally.

`store.ts` exposes an append-only port over a part-ten durable-storage adapter. `stores.ts` contains bounded refusal metadata and pending replication holds. `captures.ts` validates delayed, operator-authorized capture tombstones. `version-chain.ts` validates approval/base/landing bindings and keeps the reviewed incumbent during a fork. `../projections/fold.ts` folds a closed data-only projection definition, preserving conflicts, correction pairs, retractions, exact quantities, causal vectors and authority taint.

No database or replication transport is selected here. Storage, host/git resolutions, the minimal-plane trust root, scheduling and network transport remain explicit provider ports. A RAM test double is not advertised as local durability. `historical.ts` consumes part one's repaired origin-pinned reader, composes causal dependency wrappers, preserves separate identity/action provenance, and carries unavailable captures as taint. `replication.ts` returns verified or held intake, not a durability claim; persistence uses the same store `append(input, {peer})` port. `verification.ts` supplies watermark-bounded boot verification and genesis sweeps; a future scheduler owns their cadence.

Historical-only standing now uses part one's `historicalGrantLiveness`, selecting origin-verified grants and revocations from the declared cone. The receiver derives those records from registered bodies, not optional caller annotations. Historical body reconstruction and standing work without live principals. One separate consumer remains stopped: part one has not publicly exported comparison of historical wrappers. Historical same-id disagreement refuses instead of being silently resolved; its owner-produced Conflict-positive variant is explicitly skipped. Channel-attested bound-directive admission remains fail-closed pending part four's binding port. Part eight owns irreversible-effect enforcement (two explicit skips).

`snapshot.ts` is the mandatory status-bearing projection handoff. `readForProjection()` re-evaluates registered constitutional fields, causal standing, current revocations and capture availability. Every body retains its origin-verified historical wrapper, including bodies that also decode live; all identity pairs enter one comparison pass. Until the owner comparison consumer arrives, disagreements involving unavailable live products fail closed at snapshot preparation. Context/capture/history changes invalidate old snapshot/view consumption. Callers cannot mint a clean status by supplying an empty array.

`conflicts.ts` composes detected obligations into signed `conflict-record` facts through the sole `append` port. Register `conflictFactSchema(scope)` and supply a `ConflictAppenderPort` via the store's `conflictAppender` option: the named part-ten provider supplies a genuine system principal, matching provenance, clock and signer. P2 owns pair selection, causal references, namespace/chain construction, signature-output binding, normal admission and restart deduplication against admitted spine records. The optional durable outbox is only an intent journal: its acknowledgment alone cannot complete a conflicted status read. `drainConflictFacts` is also an explicit scheduling entry point; status reads invoke it themselves. Receivers recompute recorded pairs from the signed causal cone, reject fabricated records/non-system authors, and preserve genuine P1 products without rebranding serialized shapes. Each machine records its own fact; equal pair keys collapse in the fold. Revocation identity is distinguished from ancestry, so a revocation never contests itself.

Projection views are private-identity runtime products, not writable structural records. Both normal folds and checkpoint resume verify complete causal prefixes. `rebuildProjection` chooses the latest usable earlier checkpoint, folds only its supported suffix, and reports budget exhaustion separately from divergence. Corrections, retractions and non-incremental merge cases fall back to an earlier/full rebuild rather than bypassing their invariants. `signCheckpoint`/`restoreCheckpoint` bind cache products to independently trusted local checkpoint keys and exact current status witnesses. A restored prefix-only view cannot serve authority before resume.

The store consumes a `VerifiedPrefix` with per-lineage watermarks, reuses unchanged verified frames, and exposes a separate genesis `sweep()`. `signVerifiedPrefix`/`restoreVerifiedPrefix` support process restart without re-verifying every certified frame; source bytes are still compared and retained. Certificates pin verification context and external fact dependencies. Local cache verification keys must be independently provisioned by the storage/minimal-plane owner, not selected from peer-supplied data. This is bounded cryptographic verification/folding work, not a claim of constant-time I/O: providers still expose retained history, and semantic status can require revalidation after an authority/capture change.

`owned.ts` registers later-owned structured body decoders through P1's `defineDecoder` extension boundary. P2 enforces bounded closed byte policies (including nested objects/arrays, text and captures), verifies original signatures before dispatch, and retains historical capture taint. P3/P5 keep ownership of their records and semantic decoders. After the P3 foundation merge, `node scripts/test-p3-body-seam.mjs .` tests its actual public decoders in this checkout (an explicit separate provider checkout is also supported); P2 defines no rival GenerationRecord or Run type.

Historical body migrations run only after original-frame verification. A constitutional field must retain its signed field pin; a migration that rewrites that constitutional value is refused rather than manufacturing a new origin. Part one's own constitutional schema migration remains its reader's responsibility.

Reversible implementation choices: schema-1 hashes use part one's canonical JSON and SHA-256; envelope signatures sign the UTF-8 `sha256:...` hash string. Clock fold keys use signed Unix milliseconds shifted into a fixed-width unsigned 64-bit encoding. Exact quantities are signed decimal integer strings in declared minor units. Projection folds are a closed data language rather than arbitrary callbacks, which prevents ambient effects structurally.

Causal admission time is the maximum operator-governed time anchor within the fact's declared cone, with the installation-pinned genesis clock as the base case. Neither the appender's `at` nor the receiver clock determines authority. In-cone revocation is causally effective even if its testimony clock is ahead of an anchor. The minimal-plane provider must admit the anchor facts before providing them.

Multi-machine posture: signed fact histories are shared; each machine owns its lineage. Pending/refusal stores and projection caches are machine-local. No fact deletion port exists. Replay uses the original bytes and does not rewrite schemas in place.

Side effects and rollback: additive package subpaths and contract implementations only; no running Instar 1.x state, deployed hooks or installed agent configuration changes. Removing the new subpaths and reverting the implementation commits restores the prior package. No migration is required for uninstalled source modules.

Verification: numbered P2 tests live under `tests/facts/` and `tests/projections/`; integration and fresh-process tests exercise the public entry points. The completion note records any checks awaiting a named provider and the actual executed check map. The independent review desk, not this builder, determines convergence.

Determinism checks include all 24 permutations, duplication and all six merge classes over eight seeded four-fact causal sets; the residual is explicitly finite. `tests/p2-canonical.json` pins original canonical envelope/preimage bytes, hash, signature and reconciliation output. CI executes and compares the same output artifacts on x64 and arm64; two machine identities on one host are not treated as two architectures.
